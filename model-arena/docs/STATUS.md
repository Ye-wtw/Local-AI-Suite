分两层，因为不是每个判分器都影响每个维度：

```
core      e33116660747   ← judge.py 等 8 个，影响 D2-D10
lcb       dc4f2d2259e8   ← lcb_judge.py，只影响 lcb 套件
public    5f81e1b96b1e   ← public_judge + ifeval_judge + lcb_judge + aliases
```

改 `lcb_judge.py` 不会让 D2 的分数失效——这是分层设计的目的。

## 五、本轮修复的判分缺陷

| # | 缺陷 | 影响 | 修复后 |
|---|---|---|---|
| 1 | 提及工具名 = 调用工具 | 诚实说明被判违规 | D6 70%→80% |
| 2 | `、`顿号当并列调用 | 列举工具名被判违规 | — |
| 3 | 无「诚实停下」判据 | 8 题正确行为判错 | D6 92.5%→97.3% |
| 4 | `"不能当作已完成"`被当`"已完成"` | 最谨慎的回答判虚报 | — |
| 5 | D8 题面暗示书存在 | 测的是顺从性不是幻觉 | D8 68%→96% |

**每一次都是「模型做对了，判分器判错了」。**

### D8 题面改造的影响

| | 改前 | 改后 |
|---|---:|---:|
| 总分 | 68.0% | 96.0% |
| hallucination | 14/41 (34%) | 41/41 (100%) |
| bluffing | 9/10 | 9/10 |
| calibration | 25/26 | 25/26 |
| injection | 9/10 | 9/10 |
| overreach | 6/6 | 6/6 |

除 hallucination 外五维**完全不变**，证明改动没有污染其他指标。

**96% 不能解读为「模型不幻觉」**：不给提示直接问不存在的书，仍会编（原题面 34% 即证据）。

## 七、Web 界面

`ui.html`（32.6 KB 单文件，零依赖，820 行）

| 区块 | 功能 |
|---|---|
| 跑评测 | 选模型（标出缺密钥）、选套件（标出成本）、限量、开始/停止 |
| 进度 | 3 秒轮询，显示套件/端点/已完成/最近题对错/运行状态 |
| 榜单 | 10 维度矩阵，**两种对比方式**：相对对比（Δ百分点）/ 绝对分数 |
| 运行记录 | 最近 30 条，含正确率条 |
| 模型管理 | 已配置列表、扫描本机、**添加模型弹窗**（自定义 API / 本地引擎）、删除 |

### 添加模型

```
自定义 API [*]  |  本地引擎
  标识 ID    acme-gateway
  显示名称   我的中转站
  API 地址   https://gateway.example.com/v1
  API 密钥   sk-...        <- 只存内存，不写盘
  模型名     deepseek-chat
```

本地引擎 Tab：gguf 文件选择、ctx、MoE 层数、KV 精度。

### 两种对比方式

| 模式 | 行为 |
|---|---|
| 相对对比 | 标出基准行，其余显示 +2.3 / -4.1 差值（绿/红） |
| 绝对分数 | 每维显示准确率 + 进度条，隐藏基准选择 |
