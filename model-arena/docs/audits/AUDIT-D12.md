# D12 压缩降智 · 设计与三次迭代

> 2026-11-01。记录**三次设计错误**——这比最终数字更有价值。

## 要测什么

harness 遇到上下文上限时会压缩历史。压缩是有损的。两个不同的失败：

| 指标 | 含义 |
|---|---|
| **retention** | 压缩前能答对的，压缩后还答得对吗 |
| stability | 压缩后会不会开始自相矛盾 |

配对比较（同一批题，McNemar）。

## 三次设计错误（全部实测发现）

### v1：摘要明确说「其余省略」→ 0%

摘要写成：
```
其余项目条目因篇幅原因在压缩中省略。
```

模型回答：
```
摘要中明确指出"其余项目条目因篇幅原因在压缩中省略"，
因此无法从当前提供的文本中得知其负责人是谁。
负责人：信息缺失（未在摘要中提供）
```

**模型完全正确。** 这不是降智，是信息压根没给。**测的是诚实度。**

### v2：只保留姓氏 → 0%

摘要写成：
```
项目 PRJ-1022 有明确的负责人,姓石。
```

模型回答：
```
负责人：石（文中仅提及姓氏，未提供具体名字或职务）
```

**模型又完全正确。** 只有姓氏，问全名，本来就不可能答对。

### v3：碎片可重组 → 100%

摘要写成：
```
项目 PRJ-1022 的负责人: 姓氏 石, 职务为工程师(压缩时被拆成了两段)。
```

**碎片足够重组**（「石」+「工程师」= 石工程师），模型答对。

| 场景 | 压缩前 | 压缩后 |
|---|---:|---:|
| d12_20261101 | PASS | PASS |
| d12_20261102 | PASS | PASS |
| d12_20261103 | PASS | PASS |
| d12_20261104 | PASS | PASS |

```
保留率 100%  丢 0 题 / 捡 0 题  McNemar p=1.0000
```

## 教训

**「信息不足」和「能力下降」必须分开。**

前两次的设计缺陷是同一个：**摘要没给够信息，却把 0% 记成了降智。**
如果没逐条看模型回答，这个 0% 会被当成「压缩让模型变笨了」——一个完全错误的结论。

判断方法：**看模型是否准确指出了信息缺失**。如果它说「文中未提供」，那是诚实；
如果它编造了一个答案，那才是降智。

## 当前局限（必须写进报告）

1. **n=4 太小**，p=1.0000 是「未发现差异」，不是「证明无差异」
2. **压缩是模拟的**：本项目用确定性有损摘要器，真实 harness 压缩方式不同，数字会变
3. **压缩比 7.5%** 是摘要/原文的字符比，不是真实 harness 的压缩率
4. 只测了「事实召回」，没测「多轮一致性」（stability）
