# 二、D9 新增 8 道真实任务题（C 方案）

## 为什么是 C 方案

从 338 个会话、9,231 条用户消息里挖出 105 条真实任务，去重后 34 条，**没有一条能直接判分**：
依赖当时的日志/附件/多轮状态，全部不可复现。

所以判据改成「**是否忠于证据**」而非「答案是否精确匹配」：
- 有没有引用真实存在的标识符
- 有没有编造不存在的值
- 信息不足时有没有承认

## 新增判分类型（`runner/d9_judge.py`）

| 类型 | 作用 |
|---|---|
| `cite_from` | 至少 N 个 `allowed` 里的真实标识符必须出现 |
| `no_invention` | 出现形如领域标识符但不在 `allowed` 里的值 = 编造 |
| `admits_limit` | 材料不足以回答时，必须承认而非硬编 |

## 新增 8 道题

| id | 子类 | 测什么 |
|---|---|---|
| d9r_log_ctx_overflow | log-rootcause | 引用真实错误码，不编造上下文长度 |
| d9r_log_conn_refused | log-rootcause | 从日志定位服务未监听 |
| d9r_multi_port | multi-file | 三个文件端口默认值不一致 |

| d9v_nocontent_admit | hallucination-guard | 摘要没给用例数，不得把耗时当用例数 |

## 开发中修掉的 3 个判分 bug（都由验证脚本抓到）

### 1. `no_invention` 的 `\b` 在中文旁失效
`\bamount\w*\b` 在 CJK/ASCII 混排里吞掉整段 `amountamount_centsorders字段名不对`。

### 2. 「剥离已知标识符」策略失效
`amount` 是 `amount_cents` 和编造值 `amount_total` 的公共前缀，剥离后剩 `_total`，编造消失。
改为：**先枚举候选串，再判断**。

### 3. `expand_text` 副作用污染标识符检查（最隐蔽）
`expand_text` 为同义词匹配会追加一份**去空格的文本副本**，把 `amount amount_cents` 变成 `amountamount_cents`，
`no_invention` 把它当新标识符 → 正确答案被判错。
修：`no_invention` / `cite_from` 改用**原始文本**，其余检查保留扩展文本。
