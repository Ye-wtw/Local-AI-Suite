# 长上下文维度修复记录 · 2026-10-31

> 补长档过程中发现一个**会让整个 D7 维度失效**的设计缺陷，记录修复过程。

## 缺陷：判分器只查「名字出现」，不查「定位正确」

`judge_needle_single` 原实现：

```python
got_owner = owner and owner in txt      # 只要 owner 字符串出现在回答里就算对
```

**实测后果**：同一份 128k 文档里埋了 3 个 owner，模型把全部 owner 列一遍：

```
模型回答："文档中提到的负责人有：陈工、李经理、陈工、王总、张总、刘总"
结果：6/6 道 needle-single 题全部 correct=True
```

**测的不是「能不能定位」，是「会不会枚举」。**

## 第一次修复尝试（失败）

**方案**：每题一份独立文档，只埋一个针。
**结果**：仍然骗过 16/16。
**为什么失败**：单题内只有一个针，但判分器还是只查字符串出现——把 16 道题的 owner 全列进一个回答，每题都能找到自己的 owner。

**教训**：文档布局不解决判分逻辑的缺陷。

## 第二次修复（成功）

**改判分器**：owner 必须出现在**自己 code 的 ±200 字符内**。

```python
PAIR_WINDOW = 200
for m in re.finditer(re.escape(code), txt, re.I):
    if owner in txt[m.start()-PAIR_WINDOW : m.end()+PAIR_WINDOW]:
        paired = True
```

**向后兼容**：没有 `code` 字段的题退回原逻辑，不会静默全判错。
（现有 55 道 needle-single 题全部有 code，实际不走回退分支）

## 第三处修复：题面要与判据一致

改判分器后，正确答案「负责人是沈工」被判错——**因为题面只说「只回答负责人姓名」，没要求带 code**。

这是题目缺陷不是判分缺陷。题面统一改为：

```
文档中项目 PRJ-xxxx 由谁负责?请同时写出项目编号与负责人姓名/职务。
```
