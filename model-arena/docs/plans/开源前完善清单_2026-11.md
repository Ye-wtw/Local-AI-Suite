## 2026-11-09 追加：三项决策落地

### 决策 1 · D7 进加权 —— 已进，但加了两道闸

D7 本来就是 `scored: true`（权重 0.05）。真正的缺陷不在这里，在于**小样本也算数**：

| 缺陷 | 实测 | 修法 |
|---|---|---|
| `MIN_SAMPLE_N=10` 太松 | kv17 的 D7 只有 **n=2**，按 100% 计入总分 | `MIN_SAMPLE_BY_DIM["D7"]=100` |
| 两处入库分支只修了一处 | `LEVEL_*` 走 by_dim，`D7_*.json` 走 per-dim，后者没有门槛 | 两处都加 |
| `coverage` 只打印不排序 | Qwen3.5-9B 仅测 2/8 维度，index 98.3 排第一 | `MIN_COVERAGE=0.8`，不足者标 `partial` 且不参与排名 |

副作用（是正确行为）：deepseek-flash 的 index 从 93.1 → 92.7，
因为它原本靠 D7 的 100%（n=52）加分，而 52 题不足以代表 120 题的长上下文能力。

### 决策 2 · D12 要一点区分度 —— 未改题库，先修了判分漏洞

这一项我**没有动题目**，原因见下。但顺带修掉了一个让 D12 失真的判分器 bug：

`judge_retention` 只查「姓 + 职务」，从不核对项目编号。
「PRJ-2491 由 江总监 负责」判对 —— 那是别的项目。而同姓干扰存在的唯一目的，
就是逼模型靠编号区分，判分器却把这个唯一依据丢了。

界线要划准（我第一版划错了）：强制要求**复述**编号会把「姓陈,职务总监」这种
正确写法判错（`test_judges.py` 当场 FAIL）。正确界线是「明确写了别的编号」才算错。

**为什么没动题目**：改难度会推翻现有 24 条 D12 结论，且 D12 场景由 seed 生成、
已被判分器认为不可离线重算。要动就得重跑全部历史，属于独立一轮的工作。
建议的改法（待你确认）：把摘要里目标行的**编号也压掉一部分**，
让模型必须从上下文推断而不是照抄 —— 压缩比从 8.3% 降到 ~5%，成本不变。

### 决策 3 · 验证 start-2-evaluate.bat —— 已验，抓到一个真 bug

链路本身通了（`run.py --suite all --limit 2` exit 0，11 个维度全出结果），
但 D1 速度扫描 3/3 全报 `no metrics`。

根因：**流式解析只读 `delta.content`，而推理模型把思考写在 `delta.reasoning_content`**。
非流式那两条路径早就做了回退，流式这条漏了。症状极隐蔽 ——
`usage.completion_tokens` 报了 1000（模型真生成了 1000 token），
但 `text` 是空串、`metrics` 是 None。

实测修复前后：

```
修复前  text len: 0     metrics: null                 （completion_tokens=1000）
修复后  text len: 4328  metrics: ttft 7.95s / 53.9 tok/s
```

影响面：**任何开推理的模型，D1 速度都会全灭**。这是开源后会立刻被撞到的问题。

另外把 `long` workload 的 `HTTP Error 400` 换成了可读原因：
它要 100k token 输入，默认 4k-8k 的服务装不下 —— 提示里直接说该调 `--ctx-size` 或跳过。
