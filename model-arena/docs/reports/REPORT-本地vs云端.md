# 本地 vs 云端 · 配对对照报告

> 2026-11-01。同一套 133 题、同一套判分器、配对比较（McNemar）。
> 本地：Qwen3.6-35B-A3B-APEX-I-Compact (15.85 GB)，llama.cpp b10816，131k ctx，KV q4_0
> 云端：deepseek-flash（api.deepseek.com）

---

## 结论

**本地 85.0%，云端 94.0%，差 9.0 个百分点，统计显著（p=0.0075）。**

但**本地并非全输**：数学和代码两项本地更强。差距集中在「需要保守判断」的维度。

## 三个结论

### 1. 纯计算能力：本地不输

| | 本地 | 云端 |
|---|---:|---:|
| 数学 (D3) | **100%** | 97% |
| 代码 (D4) | **100%** | 92% |

**35B MoE 在数学和代码上超过云端。** 这两项不依赖参数量，依赖推理质量。

### 2. 差距在「保守判断」

D8 可靠性差 **40 pp** 是最大单项差距。这和我之前独立测出的结论一致：
**本地模型幻觉率 74%**（26 个不可验证对象里 24 个编造），云端只编 20%。

### 3. 差距不是「全维度落后」

110/133 题两边都对。**差距只出现在 18 道题上**（15 道云端独赢 + 3 道本地独赢）。

这意味着：**换本地模型的代价不是「什么都差一点」，而是「特定类型会出错」。**

## 必须说明的局限

| 局限 | 影响 |
|---|---|
| **D7 只有 2 题** | 上下文门槛跳过了 4 题，长上下文对比不成立 |
| **D8 只有 10 题** | canary 子集，不是完整 100 题 |
| **D9 只有 4 题** | 太小，不能量化 |
| 云端只有 flash 一档 | 没跑 deepseek-v4-pro |
| 本地只有一套配置 | 没做参数对照 |
| 云端输出 token 137,645 | 成本未核算 |

**长上下文（D7）这一项本次无法比较** —— 云端 ctx gate 跳过了 4 题，只剩 2 题。
要比较长上下文，必须用 `--max-ctx` 对齐两边，或单独跑 D7 的 120 题。

## 复现

```bash
# 本地
llama-server -m <model.gguf> --ctx-size 131072 --n-gpu-layers 99 \
  --parallel 1 --n-cpu-moe 27 -ctk q4_0 -ctv q4_0 -fa on \
  -b 1536 -ub 1536 --reasoning off --port 8080
python runner/run.py --endpoint local --suite canary --tag b0v2

# 云端
export DEEPSEEK_API_KEY=<your-key>
python runner/run.py --endpoint deepseek-flash --suite canary --skip-vram-check --tag cloud1

# 配对比较
python runner/compare_models.py --a local --b deepseek-flash --level canary
```
