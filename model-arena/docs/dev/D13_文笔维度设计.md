# D13 文笔/剧情创作 · 设计说明

## 编号：为什么是 D13 而不是需求里的 D11

需求原文写的是 "D11"，但项目里 **D11 已经被视觉维度占用**：

| 已占用 | 位置 |
|---|---|
| D11 视觉 | `runner/vision.py`、`datasets/fixtures/vision/d11_*.png`（43 张）、`run_all.py` 里 `("vision","D11","视觉")` |
| D12 压缩 | `runner/compression.py`、`suite_compression` |

D1–D12 全部占满，因此新维度取 **D13**，suite 名 `writing`。

不冒用 D11 的理由：改已占用的编号会波及现有 suite 的判分与历史结果，而铁律 3 要求改判分器后重跑历史数据——成本远高于换一个号码。

## 测什么，不测什么

**测**（全部纯规则、纯标准库、可复现）：

| 指标 | 含义 | 有效区间依据 |
|---|---|---|
| `distinct_2/3` | 不同 n-gram / 全部 n-gram | 实测 temp=0 复读时 0.984，正常 0.94–1.0 |
| `ttr` | 不同字 / 总字数 | 中文正常 0.25–0.45 |
| `cliche_hits` | 套话/AI 腔命中 | **命中即该题不通过** |
| `sensory_cats` | 视/听/嗅/触/味 五类覆盖 | 用词表+词根，不用单字 |
| `cv_sentence_len` | 句长变异系数 | 太低 = 节奏平 |
| `opening_repeat` | 连续句前两字相同的次数 | 模板化检测 |
| `turn_hits` | 转折词命中数 | 剧情推进的形式代理 |
| `dialogue_ratio` | 引号内字数占比 | 对话题用 |
| `punct_kinds` | 不同标点种类数 | **门槛 3**，实测中位数 4 |
| `han_count` | 汉字数 | 字数区间硬约束 |

**不测**：文学价值。没有任何规则能判断"写得好不好"，而本项目明令禁止 LLM 裁判（铁律 1）。
所以本维度及汇总**不出现"文笔好/差"这类措辞**，只报可复现的形式量。

> 一个必须接受的后果：形式全过 ≠ 文字动人。一个把五类感官词机械塞满、句长刻意抖动的段落，
> 也能拿 100 分。这是规则判分的边界，不是实现缺陷。

## 短篇 / 长篇

同一维度内按 subcat 分档（`_long` 后缀为长篇），指标共用一套，汇总分开报中位数：

| 档 | 字数 | 题数 |
|---|---|---|
| 短篇 | 200–800 | 12 |
| 长篇 | 2000–4000 | 3 |

理由：**"短篇写得紧凑"和"长篇能撑住"不是同一种能力**。长篇检验的是长度拉长后
`distinct_2` 不塌陷、节奏不消失。混在一起报一个总分会把这两种能力抹平。

## 采样参数必须随分数记录

实测（同一模型、同一提示词，只改采样）：

```
temp=0（贪心）        → 三个 seed 输出字节完全相同，distinct_2 = 0.984
temp=1.0/top-p=0.95  → 三个 seed 各不相同，        distinct_2 = 1.000
```

所以 `summarize()` 的返回里带 `sampling` 字段，`suite_writing` 从端点读取
temp/top_p/top_k 一并落盘。**不记录采样参数的 D13 分数不可跨模型比较。**

## 两类"没有作答"必须排除出分母

沿用铁律 6 的口径，D13 有三种记录：

| 分类 | 条件 | 是否进分母 |
|---|---|---|
| 连接失败 | `EndpointError` | 否（`n_errors`） |
| **没写汉字** | 回复中 0 个汉字 | 否（`n_no_han`） |
| 有效作答 | 其余 | 是（`n_valid`） |

"没写汉字"单列是本维度特有的：中文创作题若回一句英文
`"I need more information to answer this."`（实测 mock 端点就是这样），
所有形式指标会归零，看上去像"这个模型文笔极差"，实际是它根本没写中文。

## 两个实测校准（都是我一开始设错、被真数据纠正的）

### 1. 感官词表不能只做精确匹配

第一版用精确词表，真模型写「鱼腥气」而表里是「腥味」，写「咸涩」而表里只有「咸腥」，
于是**五类感官全覆盖的段落被判"感官不足"**。这与 AGENTS.md 反例清单里
"措辞精确匹配"是同一类错误。

修法：词表 + **双字词根**（允许后接 0–2 个汉字）。不用单字，因为单字「光」
会同时命中「光亮」和「光说」——实测「光说不做」「光明正大」误报为 0。

效果：同一批真实散文，感官覆盖从 2/3/2 类提升到 5/4/4 类。

### 2. 标点门槛不能凭想象设

第一版设 `punct_kinds >= 6`，结果 5 题全挂而文字质量并不差。实测同一模型 8 段
真实中文散文：**3,4,4,4,4,3,4,6，中位数 4**。门槛 6 等于要求达到前 10%。

改成 **3**（只拦"通篇只有句号"的极端单调，那才是这个指标真正想排除的）。
高约束题保留 5。

## 2026-11-13 完善记录：从 15 题到 24 题

### 发现的问题：题面要求了，判分器没判

审计第一版 15 题时发现 **7 处「要求了但没测」**：

| 题 | 题面写的 | 判据里有没有 |
|---|---|---|
| narrative_0001/2/3 | 至少 8 个句子 | 没有 sentence_count |
| constraint_0001 | 必须出现「铁轨」 | 没有 contains |
| constraint_0001 | 恰好包含一段对话 | 没有 dialogue_count |
| rewrite_0001 | 保留原有的全部信息 | 没有 keeps_info |
| prose_long_0001 | 至少 40 个句子 | 没有 |
| narrative_long_0001 | 至少 50 个句子 | 没有 |

这不是笔误，是**最危险的一类判分缺陷**：模型完全不按要求写（不写铁轨、写十段对话、
丢掉改写题一大半信息）也照样拿 100 分。AGENTS.md 反例清单里
「判分分支查错对象 → 44 道 exec 题从未执行过」是同一类。

### 修法一：补齐 4 个判据

runtime/d13_prose.py 新增：

| 判据 | 作用 |
|---|---|
| sentence_count | 句数上下限（对应「至少 N 句」） |
| dialogue_count | 引号段数（对应「恰好一段对话」，用 in_range [1,1]） |
| contains / not_contains | 指定意象必须出现 / 禁用词不得出现 |
| keeps_info | 改写题逐点核对信息有没有丢，每个信息点支持别名 |

keeps_info 说明：改写题不能判「改得好不好」，但**能判信息有没有丢**。
题目给出若干「必须保留的信息点」，每点的任一别名出现即算保留：

```
python
{"type": "keeps_info", "op": "gte", "min": 1.0,
 "value": [["屋子", "房间"], ["桌"], ["灯"], ["灰", "灰尘"],
           ["窗"], ["街"], ["没人", "空无一人", "无人"], ["天色", "很晚", "夜深"]]}
```

### 修法二：把「覆盖率审计」做进 --verify

光改这一版不够 —— 下次加题还会漏。所以 gen_d13_prose.py 新增
audit_coverage(rows)：逐题用正则从**题面文字**里提取硬要求，
再检查判据里有没有对应的 check 类型。

```
[覆盖] 题面的每条硬要求都要有对应判据
   PASS 24 题的题面要求全部有对应判据
```

覆盖规则：必须出现「X」→ contains；不得出现/不许用 → cliche_hits；
至少 N 个句子 → sentence_count；恰好一段对话 → dialogue_count；
对话占比 → dialogue_ratio；改写保留 → keeps_info；感官 → sensory_cats；
标点 → punct_kinds；判据类型必须在 SUPPORTED_CHECKS 里。

### 一个过程中的教训

给 gen_d13_prose.py 插入新 verify 时用了错误锚点，导致文件里
**出现两个 def verify** —— Python 取最后一个，我新加的审计被旧版覆盖，
第一次跑 verify 时「审计没生效」却毫无报错。这类「重复定义静默覆盖」
和项目里「改代码后旧进程不重载」是同一性质的坑：**看起来跑了，其实跑的旧代码**。
以后往已有函数里插入改动，插入后要 grep 一遍同名定义的数量。
