# UI v3 · 选项卡布局与预设速度页

> 2026-11-02　|　`ui.html` 37605 字符 / 968 行

---

## 为什么改

v2 是 5 个卡片纵向堆叠，页面高度远超视口，看榜单要滑到底、跑评测要滑回顶部。
v3 把每个区块收进独立选项卡，**页面高度 == 视口高度，不需要滚动**。

```
v2: 5 卡片堆叠 → body.scrollHeight > 2×viewport
v3: 5 选项卡    → pageHeight 772 == viewport 772
```

## 布局

```
▸ 跑评测     评测表单 + 进度（原两卡合并，按下开始就在同一屏看到进度）
▤ 榜单       10 维度矩阵 + 相对/绝对两种对比
⚡ 预设与速度  7 个本地预设的实测速度与启动参数
◷ 运行记录    最近 30 条历史结果
⚙ 模型管理    已配置模型 / 添加模型 / 扫描本机
```

### 为什么把「进度」并入「跑评测」

原设计里点「开始评测」后，进度卡在下一屏，要滚下去才看到动没动。
合并后按下按钮就在同一屏看到「运行中 · smoke · 已完成 5 题」。

## 预设页

### 数据从哪来

预设清单与参数、速度数字，来自**三个不同性质的文件**，各自职责不重叠：

```
Llama-Rig configs/*.config.toml    20 份   ← 配置与参数（TOML，实时解析）
config/profiles.json                1 份   ← 本项目导入的配置（argv 解析）
config/preset_speed.json                   ← 速度序列 A（生成器产出）
Llama-Rig configs/model-catalog.json       ← 速度序列 B + 模型元数据
        ↓  presets.py 合并（两条序列并排，不平均）
GET /api/presets   /  POST /api/presets/scan
        ↓
ui.html 预设与速度 Tab
```

**参数不再有第二份拷贝。** 早先 `gen_preset_speed.py` 里手抄过一张
`PROFILE_PARAMS`（只有 apex-256k 一条），改一次配置就要改两处，那处迟早是旧的。
现已删除：参数一律从 TOML/argv 实时解析，21 套配置全覆盖。

**数字不手写进 UI。** 改数字 = 改实测文档 + 重跑生成器。

## 批量队列页

选预设 → 点编号定顺序 → 选套件 → 开始。**顺序就是执行顺序**
（显存最紧的排前面，失败时省时间）。

### 两个实测踩到的前端缺陷（已修，写下来防再犯）

**1. 事件闭包捕获的元素在列表重建后失效。**
最初的实现是"每次勾选都重建整个列表"。实测表现：选 2 个预设，只有 1 个
被真正选中 —— 第二个点击时，闭包里的 `cb` 指向的节点已经不在文档里，
而新节点上的 `checked` 是按旧状态渲染的，于是把第一个覆盖成了未选中。
现在改成**原位更新**：只改编号徽章和 checked，不重建 DOM。

**2. 重建会把滚动位置弹回顶端。**
34 个预设要滚着找，每次勾选都跳回顶部就找不到刚才点哪了。
现在重建前保存 `scrollTop`、重建后恢复。

界面上还有两处刻意的取舍：
- 「总耗时」只给**次数与题量**，不给小时数：实测 D2 是 23.6 s/题、D4 是 1 s/题，
  差 23 倍，一个统一的"每秒题数"会差出一个数量级。
- 标 `launcher` 的预设（如 `C1-Cyber`，引擎是 strata CLI）**禁用勾选**并说明原因：
  它不吃 TOML 参数，排进队列只会得到"起不来"。

### 在跑识别

页面顶部有一条状态栏，分三种：

| 状态 | 含义 |
|---|---|
| 绿色「运行中」 | 服务自述的 `model_path` + `n_ctx` 与某套预设一致 |
| 黄色「未认领」 | 有服务在跑，但对不上任何预设（单独列出端口与别名） |
| 灰色「未运行」 | 本机没有模型服务在监听 |

对应行本身会高亮，并在名字下方标出「已识别：模型文件与上下文长度都一致」。

**为什么不用进程名/命令行**：本机实测 `Get-CimInstance Win32_Process` 与
`tasklist` 均被拒绝访问，拿不到启动参数；服务自述是唯一可用的事实来源。

## 已知局限

1. 预设速度是 **2026-10-06** 的实测，不是当前实时数据。改硬件或驱动需重测。
2. 21 个预设里只有 7 个有 GUI 实测速度、9 个有目录实测速度，其余留空（宁缺不编）。
3. `config/preset_speed.json` 需手动重跑生成器更新（未接进 `handoff_check.py` 的自动校验）。
