# AGENTS.md — model-arena 项目规则

> 给接手的 AI agent 和人类贡献者。项目内实现细节见 `docs/dev/HANDOFF.md` / `docs/dev/STRUCTURE.md`。
> 使用方式见 `README.md`。

## 这个项目是什么

在**自己的机器上**评测大模型：同一套题、同一套判分器，比较本地模型与云端 API，
并找出最适合自己硬件的启动参数。

## 铁律（违反即数据不可信）

1. **不用 LLM 当裁判。** 全部规则化判分。LLM 裁判有偏好，且不可复现。
   判分器在 `runner/*_judge.py`，每题自带 `checks` / `expect`。

2. **结论区分「实测」与「推断」。** 样本 <100 题只能说方向，不能量化差距。
   报告里必须写清 n、是否独占 GPU、覆盖度。

3. **判分器比模型更容易出错。** 本项目实测：一轮修掉的 9 个缺陷里，
   7 个在判分/基础设施，只有 2 个是真模型弱点。**改判分器后必须重跑历史数据**，
   新旧数字不可直接比较。

4. **改判分器前先看这个反例清单**（都实际发生过）：
   - 「回答长度 > 250 字符 = 编造」→ 把 352 字全对的答案判错
   - `\b` 正则在 CJK/ASCII 混排里失效 → 吞掉整段文本
   - 「剥离已知标识符再扫描」→ 公共前缀让编造值消失
   - `expand_text` 追加去空格副本 → 污染标识符检查
   - 摘要「明确说信息缺失」→ 模型答「不知道」被判 0 分，实际它是对的
   - **SQL 参考解 JOIN 错列**：schema 是 `orders.customer TEXT` 与
     `customers.name TEXT`，参考解写成 `c.id`（INT）。云端写了正确的
     `c.name`，被判 0/3。写 SQL 题必须核对列类型
   - **exec 题面不含文件**：文件在 `exec.files`，题面只有一句指令。
     模型回「请粘贴文件」被判错，实际它没法做。用 `_prompt_for()` 拼接
   - **判分分支查错对象**：exec 块在题库行 `q`，不在 baseline `b`。
     `if b.get("exec")` 恒为 False → 44 道 exec 题从未执行过
   - **拒答判分被绕开**：`REFUSE` 词表命中「不能撕破脸」这类无关用法，
     `HARM_ARTIFACT` 只查原始词（模型把「恐吓信」改叫「施压信」）。
     判拒答要看**是否交付了可用成品**，不是看开头有没有拒绝词
   - **改代码后旧进程不会重载**：跑测中途修判分器，正在跑的进程仍用旧代码。
     修完必须重跑受影响维度，不能拿旧结果当新结果

   - **答案提取抓了题面里的举例**：D10 题面写着「用 UCI 格式(如 e2e4)回答」,
     `parse_chess_answer` 全文扫描 UCI 正则,先命中了那个 **e2e4 例子**,而不是末尾的
     `answer: Nf7#`。模型答对却判错。修法:**先只取 `answer:` 行**,再在那一行里做匹配。
     同类风险:任何「题面带示例格式」的题型(D3 数值示例、D5 JSON 示例)都可能中招。
   - **取答案行只看第一个非空行**：模型会写出 `Answer:**` 这种只有 Markdown 粗体标记的行,
     第一版补丁取到 `**` 当答案,`no square found` → 把一道原本判对的题翻成判错。
     修法:扫**所有** `answer:` 候选,strip 掉 `*`,取**最后一个非空**的。
     教训:修判分器后必须**重算全部历史结果**看有没有反向翻转,只看单题通过不算修好。
   > 2026-11-01 全量跑测（1949 题 × 2 端点）一次抓出 6 个缺陷，
   > **6 个里 4 个在判分器**，只有 1 个是真模型弱点（幻觉）。
   > 修完后云端 D9 从 70% → 92.7%，其中 config-fix 从 11% → 100%。

5. **「信息不足」和「能力下降」必须分开。** 题目没给够信息时，模型说「不知道」
   是**正确行为**，不是降智。判断方法：看模型是否准确指出了缺失。

6. **连接失败 / 超时 ≠ 答错，分母只算有效题。**
   `endpoint.chat()` 抛 `EndpointError` 的题(`WinError 10061` 连接被拒、超时、
   服务 503)说明**请求没送到**,模型没有作答的机会。把它算成"答错"会系统性
   压低分数,而且压低多少完全取决于当时服务稳不稳,与模型能力无关。

   实测代价:2026-11-05 那晚 D2 552 题里 257 题报 `WinError 10061`,
   按"错"计入后显示 **45.3%**;而拿到答案的 295 题里对了 250 题,真实是 **84.7%**。
   同一批题因为一个分母口径,差了 39 个百分点。

   正确写法(所有 suite 必须一致):`valid` = 无 `error` 的记录;
   `n_valid`/`n_errors` 分开报;`accuracy` 分母用 `n_valid`;
   同时保留 `accuracy_with_errors` 便于对照。
   并且**把错误题的 id 存进 `error_ids`**,补跑时只补这些。

   ⚠ 只有"连接失败"才能补跑。**答错不能补跑**——那是 best-of-N,
   不再是 pass@1,补过的一定要标 `refilled` 后缀单独成栏。

7. **不自行启动 GPU 任务。** 用户说「跑」才跑。跑前先 `nvidia-smi`。

## 改完文档要自查

```bash
python runner/doccheck.py --strict
```

它会核对：文档里写的每个 `python runner/xx.py` 是否真实存在、
每个 `--suite <name>` 是否是 run.py 真接受的。
**写文档最容易凭记忆写命令，这个工具把这类错误变成可检测的。**

## 加新题目的正确姿势

1. **写生成器，不手改 jsonl。** 手改会在追加时覆盖已有行。
   参考 `scripts/gen_d9_real.py`。
2. **生成器必须有 `--verify`**，双向验证：
   - 正确回答必须判对
   - 空回答 / 编造 / 只回「好的」必须判错
3. **判据要能表达「忠于证据」**，不是「措辞精确匹配」。
   用 `cite_from`（引用真实标识符）/ `no_invention`（不编造）/
   `admits_limit`（承认信息不足）。

## 加新维度的正确姿势

1. 新建 `runner/<dim>.py`，只做三件事：造题、判分、统计
2. 在 `run.py` 加 `suite_<dim>()`，注册到 `--suite` choices
3. 加汇总打印（结果汇总段）
4. **用假端点先验证**，再上真模型

## 常见坑

| 坑 | 症状 | 解法 |
|---|---|---|
| `chat()` 不发 `max_tokens` | 单题跑到耗尽上下文 | 显式传，默认 16384 |
| `urlopen(timeout=)` 只约束单次读 | 生成中永不超时 | 用墙钟 deadline |
| `tempfile.mkdtemp()` 是 0o700 | `PermissionError` | 用 `makedirs` + `rmtree` |
| `--parallel` 默认 4 | 上下文被切成 1/4 | 强制 `--parallel 1` |
| `--reasoning on` | `content` 为空，全在 `reasoning_content` | 加 `--reasoning off` |
| `Select-Object -First` 截断管道 | 假 `EXIT=-1` | 用 `Out-String` |
